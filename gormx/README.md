# gormx

GORM 数据库封装，支持多种数据库类型和读写分离，提供统一的连接管理。

## 支持的数据库

- MySQL
- PostgreSQL
- SQL Server
- Oracle（`sijms/go-ora` + `godoes/gorm-oracle`，纯 Go 实现，无 CGO、无需安装 Oracle 客户端）
- SQLite
- DM（达梦）

## DSN 拼装与转义

只配 `host`/`port`/`username`/`password`/`database` 时，DSN 由 `gormx/dsn.go` 的 `dsnDialects` 拼装。
每条登记项同时描述三件事：形状（模板，用 `{user}` `{password}` `{host}` `{port}` `{database}` `{schema}`
命名占位符，`[ ]` 包起来的片段在占位符为空时整段省略）、各位置的编码方式、参数拼接方式（`?`/`&`/`;`/空格）。
`genDSN` 里没有任何按类型分支，新增数据库类型只加一条登记。

命名占位符取代了早先的 `%s`：位置模板要求占位符个数与顺序和 `Sprintf` 实参严格一致，改模板时漏同步
不会报错，而是把 `%!(EXTRA string=...)` 拼进 DSN。密码中含特殊字符时的行为按驱动而定：

| 类型 | 处理方式 |
|------|----------|
| Oracle | 用户名/密码/服务名按 URL 规则转义，`args` 走 query 编码（`SERVER` 逗号分隔多节点） |
| PostgreSQL | 值含空白/引号/反斜杠时用单引号包裹并转义；`schema` 映射为 `search_path='...'`，未配置则整段省略 |
| SQL Server | **DSN 带 `odbc:` 前缀**，值含 `;` `{` `}` 或首尾空白时用 `{}` 包裹、内部 `}` 双写 |
| MySQL | 库名与 `args` 按 URL 编码；用户名密码无转义机制，含 `@` 属驱动限制，建议改用 `dsn` 字段 |
| 达梦 | 驱动不做 URL 反解，原样传递（`args` 值含 `&` 无法表达，属驱动限制）；`database` 即 schema，落在 `?schema=` 上 |
| SQLite | `database` 为文件路径，未配置时落到 `file::memory:?cache=shared`；`args` 用 `&` 追加 |

`schema` 只在 PostgreSQL（`search_path`）和达梦（`?schema=`）上有意义，其余类型即使配置了也不会拼进 DSN。

SQL Server 的 `odbc:` 前缀不是可选项：`go-mssqldb` 的 `msdsn` 在**不带前缀**时按 ADO 规则
无脑以 `;` 切分，完全不认花括号，`password=p;w` 会被截成 `{p`；带前缀才走 ODBC 状态机，
支持 `{}` 与 `}}`。三种 DSN 类型（`sqlserver://`、`odbc:`、ADO）里只有 ODBC 能安全表达特殊字符。

密码里含 `@` 不影响连接：各驱动都以「最后一个 `@`」作为用户信息与主机的分隔符，所以
`p@ss/w` 这类密码在 Oracle/MySQL/PostgreSQL/SQL Server/达梦上都能正常使用（已逐个用驱动
解析函数与实际 Oracle 登录验证）。真正需要转义的是 `/`、`?`、`#` 这类会破坏 URL 结构的字符。

## Oracle 说明

Oracle 不再依赖 godror/ODPI-C，`CGO_ENABLED=0` 即可交叉编译。连接串有两种写法：

- 配 `host`/`port`/`username`/`password`/`database(服务名)`，按统一模板拼装成
  `oracle://user:pass@host:port/service`，用户名/密码/服务名中的 `@`、`/` 等特殊字符会被正确转义；
  `args` 会作为 URL 查询参数追加（如 `SSL`、`CONNECTION TIMEOUT`，`SERVER` 支持逗号分隔多节点）。
- 直接写 `dsn`，必须是 `oracle://` 开头的 URL 形式；旧版 godror 的 `user/pass@host:port/service`
  写法不再支持。

```yaml
datasource:
  db_type: "oracle"
  host: "10.0.0.10"
  port: 1521
  username: "dagine"
  password: "p@ssw0rd"
  database: "ORCLPDB1"        # 服务名
  args:
    - name: "CONNECTION TIMEOUT"
      value: "90"
```

注意：Oracle 11g 不支持 IDENTITY 列，自增主键会生成 `GENERATED BY DEFAULT AS IDENTITY` 而报
`ORA-02000`，请改用序列/触发器或显式赋值主键；12c 及以上可直接用 `autoIncrement`。

## 默认连接池参数

| 参数 | 默认值 |
|------|--------|
| MaxOpenConn | 100 |
| MaxIdleConn | 10 |
| ConnMaxLifeTime | 3 小时 |
| ConnMaxIdleTime | 45 分钟 |

## 配置文件

默认读取 `conf/application.yaml`：

```yaml
datasource:
  enable: false                # 是否启用
  strict: true                 # 是否为下游必需，如为 true 则启动时 panic
  db_type: "mysql"             # mysql|postgres|sqlserver|oracle|sqlite|dm
  host: "127.0.0.1"
  port: 3306
  username: root
  password: "xxx"
  database: mydb
  # 或者直接使用 DSN
  # dsn: "root:pass@tcp(127.0.0.1:3306)/mydb?charset=utf8mb4&parseTime=True&loc=Local"
  # 主从配置
  # masters:
  #   - host: "127.0.0.1"
  #     port: 3306
  #     username: root
  #     password: "xxx"
  #     database: mydb
  # replicas:
  #   - host: "127.0.0.1"
  #     port: 3307
  #     username: readonly
  #     password: "xxx"
  #     database: mydb
  args:
    - name: charset
      value: utf8mb4
  log_mode: "info"
  max_idle_conn: 10
  max_open_conn: 100
```

## 使用示例

### 初始化

```go
import "github.com/jasonlabz/potato/gormx"

// 从全局配置初始化
func initDB(_ context.Context) {
    dbConf := configx.GetConfig().Database
    if !dbConf.Enable {
        return
    }
    gormConfig := &gormx.Config{}
    err := utils.CopyStruct(dbConf, gormConfig)
    if err != nil {
        panic(err)
    }
    gormConfig.DBName = gormx.DefaultDBNameMaster
    _, err = gormx.InitConfig(gormConfig)
    if err != nil {
        panic(err)
    }
}
```

### 获取数据库实例

```go
// 按名称获取
db := gormx.GetDB("mydb")

// 获取默认主库/从库
masterDB := gormx.DefaultMaster()
slaveDB := gormx.DefaultSlave()

// 连接检查
err := gormx.Ping("mydb")

// 关闭连接
gormx.Close("mydb")
```

> 推荐使用 [gentol](https://github.com/jasonlabz/gentol) 工具自动生成 DAO 层代码。

## 特性

- 主从读写分离（基于 gorm dbresolver 插件）
- 连接池管理
- Mock 模式支持测试
- 自动 DSN 生成（从 Host/Port/User/Pass 构建）
- 支持 DSN 直连或参数拆分两种配置方式
